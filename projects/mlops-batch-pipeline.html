MLOps Batch Pipeline

A small pipeline that turns OHLCV data into a trading signal, built to never fail silently.

2026 PythonPandasDocker
View source on GitHub ↗ All projects
// 01

Fail loud, fail specific

Most scripts fail one of two ways: a raw traceback that means nothing to whatever called them, or worse, silently wrong output. This pipeline gives every identifiable failure mode its own path: missing config fields, malformed YAML, a missing required column, a rolling window larger than the dataset itself. Each one writes a structured error into metrics.json and exits non-zero, so a calling system knows exactly what went wrong without parsing logs.

Every stage validates before it acts. A failure at any point writes a labeled error instead of crashing blind.

// 02

Deterministic on purpose

Run this pipeline twice on the same input and config, and signal_rate comes out identical both times. That's not an accident, it's a design constraint. Only latency_ms is allowed to vary between runs, because that's a measurement of the run itself, not the correctness of the computation. Determinism is what makes a pipeline like this testable with plain equality assertions instead of fuzzy tolerances.

// 03

One command, no assumptions

The Docker build bundles the sample data and config together, so docker run --rm just works. No flags, no volume mounts, no "works on my machine." Anyone can verify the whole thing end to end without first reading a setup guide.
