Page Pulse

Paste a URL, get its vitals: status, response time, title, missing alt text, word count.

2026 Node.jsExpress
View source on GitHub ↗ All projects
// 01

Keeping the parser innocent

The function that reads a page's vitals has no idea that fetch, timeouts, or HTTP status codes exist. It takes HTML text in, and returns a vitals object out, nothing else. That separation is what makes the test suite plain input and output assertions instead of mocked network calls: faster tests, and a parser you can trust independent of whatever the network is doing that day.

The parser sits behind a hard boundary: it never sees a network call, only text.

// 02

Five ways to fail, five different answers

Instead of one generic 500 for anything that goes wrong, Page Pulse returns one of five typed codes: INVALID_URL, NOT_HTML, FETCH_FAILED, TIMEOUT, INTERNAL_ERROR. A caller, a script, a CI pipeline, another engineer, can branch on exactly which one happened instead of guessing from a message string.

// 03

A 404 is not Page Pulse's problem

If the target page returns a 404, that's still a successful audit, Page Pulse correctly reports "this page is a 404." Only Page Pulse's own failure to complete a check counts as an error. It's a small distinction, but it's the one that decides whether the tool is honest about what it's measuring.
