SynapseAI

Seven AI agents that write, run, and grade their own machine learning code, so a full benchmarking pass takes minutes instead of days.

// 01

Why a blackboard, not a chatroom

The obvious way to build a multi-agent system is to let agents message each other directly: EDA agent tells Feature Engineering agent what it found, which tells Model agent what to train on, and so on. That works for three agents. It gets fragile fast past five, because every agent needs to understand every other agent's message format.

SynapseAI uses a Blackboard architecture instead, a pattern from 1980s expert systems, repurposed for LLM agents. There's one shared state object, validated by Pydantic, that every agent reads from and writes to. No agent needs to know how any other agent talks. It only needs to know the blackboard's schema: what fields exist, what they mean, whose job it is to fill them in.

The Supervisor is the only agent that decides order. Everyone else just reacts to what's currently on the board.

Every agent reads and writes through one shared, Pydantic-validated state object. None of them talk to each other directly.

// 02

The pipeline, agent by agent

Once the Supervisor kicks things off, six specialists run in sequence, each one handing a richer blackboard to the next:

EDA profiles the raw dataset and writes its findings back. Preparation handles cleaning and encoding. Feature Engineering generates new candidate features. Model trains across 9 algorithm families, from Logistic Regression to CatBoost, and produces a leaderboard.

Then it gets interesting. Critic doesn't just record the leaderboard, it checks it for overfitting and underfitting signals. If something looks wrong, it can send the pipeline back to Model for another pass instead of quietly accepting whatever came out first. Only once Critic is satisfied does Report write the final summary.

The Critic agent is the one quality gate in the pipeline. It can loop the process back instead of accepting the first result.

// 03

Letting an LLM write code safely

Agents in SynapseAI don't call a fixed library of pre-written functions. Each one generates real Python with a local LLM (Ollama running Qwen3:8B), and that code actually executes. That's what makes the system flexible enough to handle datasets it has never seen, and it's also the most dangerous part of the design if left unconstrained.

So generated code passes through a sandbox before it ever runs: an AST validator parses the code into a syntax tree and inspects it structurally before execution, rather than trusting it blindly. An import whitelist means only approved libraries are reachable. A forbidden-function check blocks calls like eval or os.system. A runtime timeout kills anything that runs away, and each execution gets an isolated workspace that's cleaned up afterward.

None of this is theoretical. It's the difference between "an LLM suggested some code" and "an LLM's code ran unsupervised on my machine."

Worth knowing

The project's own README tags it Status: Research, not production. Multi-agent systems that generate and execute their own code are still an open problem industry-wide, and being upfront about that felt more honest than dressing it up as a finished product.
